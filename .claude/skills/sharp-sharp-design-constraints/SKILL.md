# Sharp Sharp — Design Constraints

A running list of hard "don'ts" for any visual or UI work on this app. These
rules apply automatically to every design/coding session on this project,
not just the one that created this list.

Treat this list as absolute constraints, not preferences. If a design
suggestion violates one of these, flag it or rework it rather than
proposing it as-is, even if it's a common/expected pattern for the type of
screen being built.

## Color

- No harsh gradients
- No pure white backgrounds (paper/off-white or a warm neutral only)
- No rainbow coloring (avoid using many hues at once -- pick a restrained,
  deliberate palette)
- No neon colors
- No generic/basic pastel color palette (avoid the "safe" pastel-app look)
- No purple-and-black "night mode" aesthetic

## Icons & Imagery

- No Lucide icons -- pick one icon family and stay consistent with it
  throughout
- No emojis anywhere in the product -- icons only, never emoji as UI or
  copy decoration
- No sparkle icons (magic/AI visual cliche)
- No animated arrows
- No colored "lip" stripe / ribbon accent bar

## Effects & Materials

- Use drop shadows sparingly -- not as a default on every surface
- No liquid glass / glassmorphism effects
- No skeleton loaders (use a different loading pattern)
- No radial orbs / glow blobs
- No dot-grid background textures

## Layout

- No "three featured cards in a row" layout pattern
- No bento-grid layouts
- No terminal-window motif
- No three-tier pricing-card pattern (not applicable to this app, but noted
  as a pattern to avoid generally)

## Typography

- No Inter
- No Geist
- No Space Grotesk

## Copywriting

- No em dashes in UI copy or written content
- No "It's not X, it's Y" sentence construction
- No checkmark bullet points
